# ブログ記事（SWELL / note / X）

参考 HP のリンクを起点に記事を 1 本作り、次の 3 チャンネルに展開する。

| 出し先 | 自動化 | やり方 |
| --- | --- | --- |
| WordPress（SWELL） | 自動 | `scripts/wp_post.py` で下書き投稿 |
| X | 自動（要 API キー） | `scripts/x_post.py` で投稿。既定は dry run |
| note | 半自動 | 公開 API がないため、原稿を出力して貼り付けは手動 |

## この作業のゴール

次の 3 つがそろったら終わり。

1. `blog/drafts/YYYY-MM-DD-<slug>.md` に記事本文がある（front matter 付き）
2. WordPress に**下書き**として入っていて、front matter に `wp_id` が書き戻されている
3. `blog/drafts/YYYY-MM-DD-<slug>.x.txt`（X 用）と `.note.md`（note 用）がある

公開ボタンは押さない。公開は必ず人が確認してから。

## 手順

1. **参考 HP を読む。** WebFetch で本文を取得する。何を扱っているサイトか、どういう構成か、
   一次情報（運営会社・料金・条件）がどこに書いてあるかを掴む。
2. **構成を決める。** 参考 HP は「見本」であって「原稿」ではない。見出し構成をそのまま
   コピーしない。読者が知りたい順に組み直す。
3. **数字と事実を確認する。** 料金・利回り・実績・キャンペーン期限・運営会社名は、
   必ず**公式サイト**で裏を取る。参考 HP に書いてある数字をそのまま写さない
   （古い可能性がある）。確認できなかった項目は書かないか、「〜と案内されている」と書く。
4. **書く。** 下の「書き方のルール」に従う。`blog/drafts/` に保存する。
5. **チェックリストを通す。** 下の「公開前チェック」を上から全部見る。
6. **WordPress に下書き投稿する。**
   ```bash
   python3 scripts/wp_post.py blog/drafts/2026-07-26-example.md --dry-run   # 確認
   python3 scripts/wp_post.py blog/drafts/2026-07-26-example.md             # 下書き投稿
   ```
   直したら `--update` を付けて再実行すれば同じ記事を更新できる。
7. **X 用の原稿を作る。** `.x.txt` に書き出して dry run で文字数を確認する。
   ```bash
   python3 scripts/x_post.py blog/drafts/2026-07-26-example.x.txt          # dry run
   python3 scripts/x_post.py blog/drafts/2026-07-26-example.x.txt --yes    # 投稿
   ```
8. **note 用の原稿を作る。** `.note.md` に書き出す。note は見出しが h2/h3 の 2 段階までなので
   ブログ版より構成を浅くする。ブログへの導線を最後に置く。

## ファイルの形

```markdown
---
title: 記事タイトル
slug: example-slug
categories: 投資,クラウドファンディング
tags: バフェッサ,無料セミナー
excerpt: 検索結果に出る 100 字程度の要約。
source: https://example.com/参考にしたページ
status: draft
---

## 見出し

本文。
```

- `title` は必須。`slug` は半角英数とハイフン。
- `categories` / `tags` はカンマ区切り。既存のものと名前が一致すれば紐づく。
  新規作成したいときは `--create-terms` を付ける。
- `wp_id` は投稿時に自動で書き戻されるので、手で書かなくてよい。

使えるのは見出し（`##`〜`####`）・段落・箇条書き・番号付きリスト・表・引用・画像・区切り線・
コードの 9 種類。これらは `scripts/md2blocks.py` が Gutenberg ブロックに変換する。

## 書き方のルール

<!-- TODO: 実際の文体は本人に確認して確定させる。以下は暫定。 -->

- 常体・敬体: **敬体（です・ます）**
- 一人称: <!-- TODO -->
- 1 記事の目安: 3,000〜5,000 字
- 見出しは `##`（h2）から始める。h1 はタイトルが使う。
- 結論を先に書く。前置きの体験談で引っ張らない。
- 表・箇条書きを使って、比較できるものは比較の形にする。

## 公開前チェック

案件記事（アフィリエイト・PR）で特に落としやすいところ。上から順に確認する。

- [ ] **広告表記** — 対価を受け取る記事なら「PR」「広告」を、読者がすぐ気づく位置
      （記事冒頭）に書いたか。ステマ規制（景品表示法の指定告示）の対象になる。
- [ ] **断定していないか** — 「必ず」「確実に」「絶対に儲かる」を書いていないか。
      投資・クラファン系では断定的な利益の見込みを示す表現を使わない。
- [ ] **元本保証と読める書き方をしていないか** — 「元本保証」「ノーリスク」は書かない。
      元本割れの可能性がある商品なら、そのリスクを本文に書く。
- [ ] **最上級表現の根拠** — 「No.1」「日本一」「最安」を書くなら調査主体・時点・
      調査方法の出典を添える。出せないなら書かない。
- [ ] **数字の出典** — 料金・利回り・実績・人数は公式ページで確認済みか。
      確認日を本文か末尾に入れる（情報は古くなる）。
- [ ] **キャンペーン期限** — 期限付きの内容は「◯年◯月時点」と明記したか。
- [ ] **引用の扱い** — 参考 HP の文章をそのまま写していないか。引用するなら
      引用部を明示して出典を書き、あくまで自分の文章が主になるようにする。
- [ ] **ASP の規約** — 案件ごとに禁止されている表現（誇大表現、特定のキーワードでの
      集客など）がないか、提携時の条件を確認したか。
- [ ] **リンク** — アフィリエイトリンクが正しいか、`rel="noopener"` が付いているか
      （`md2blocks.py` が外部リンクに自動で付ける）。

## 出力先

| ファイル | 中身 |
| --- | --- |
| `blog/drafts/YYYY-MM-DD-<slug>.md` | ブログ本文（WordPress へ投稿する元） |
| `blog/drafts/YYYY-MM-DD-<slug>.x.txt` | X の告知ポスト。空行 2 つか `---` でスレッド分割 |
| `blog/drafts/YYYY-MM-DD-<slug>.note.md` | note 用（手動で貼り付ける） |

## 準備（初回だけ）

```bash
cp .env.example .env   # WP_URL / WP_USER / WP_APP_PASSWORD などを埋める
```

WordPress のアプリケーションパスワードは、管理画面 → ユーザー → プロフィール →
「アプリケーションパスワード」で発行する。エックスサーバーで 403 が返る場合は、
サーバーパネルの WAF 設定を確認する。
