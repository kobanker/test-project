## スクリーニング A：ネットキャッシュ比率 1.0 超の割安株

### 抽出条件（バフェット・コードのスクリーニング画面で指定）

| 項目 | 条件 |
| --- | --- |
| PER（会予） | 8 倍以下 |
| 時価総額 | 500 億円以下 |
| 自己資本比率 | 50% 以上 |

### 追加フィルタ（一次抽出後に各社の財務データで計算）

1. **負債 < 流動資産** であること（負債は負債合計を使う）
2. **ネットキャッシュ（NC）** を計算する
   - 基本形：`NC = 流動資産 − 負債合計`
   - 投資有価証券を加えた形（今回採用）：`NC = 流動資産 + 投資有価証券 − 負債合計`
   - ※清原達郎式では投資有価証券を 70% 掛け（×0.7）で算入する。掛け目を入れるかは
     好みだが、保守的に見るなら ×0.7 を推奨。どちらを使ったかをリストに明記すること。
3. **NC 比率 = NC ÷ 時価総額** を計算
4. **NC 比率 > 1.0** の銘柄のみ残し、**NC 比率の降順**で並べる

## スクリーニング B：中型・高配当・業績良好株

| --- | --- |
| 時価総額 | 500 億円以上 |
| 自己資本比率 | 50% 以上 |
| 配当利回り（会予） | 3〜4% |
| PER（会予） | 10〜15 倍 |

### 追加チェック（一次抽出後に 1 銘柄ずつ）

1. **四季報コメントのキーワードチェック**：見出し・本文に
   「**最高益**」「**増配**」「**連続**」のいずれかがあれば ★ でハイライト
   （四季報オンライン or 証券会社アプリの四季報表示で確認）
2. **月足チャートの形状**：5〜10 年の月足で高値・安値が切り上がっているかを目視し、
   「右肩上がり / 横ばい / 右肩下がり」の 3 区分で記録

## スクリーニング C：サブスク型ビジネスの押し目候補

### 抽出条件

| 項目 | 条件 |
| --- | --- |
| PBR | 1〜3 倍（**低い順**に並べる） |
| ROE | 10% 以上 |
| RSI（14 日） | 30 以下（売られすぎ圏） |
| ビジネスモデル | サブスクリプション型（ストック収益比率が高いこと） |

### 補足

- バフェット・コードに「サブスク」の機械的フィルタはないので、二段階で絞る。
  ① PBR・ROE を バフェット・コードのスクリーニングで指定して一次抽出
  ② 事業内容欄・決算説明資料で「サブスクリプション」「リカーリング」「ARR」「MRR」
    「ストック収益」等の記載がある銘柄だけ残す（SaaS、通信、保守・メンテ、月謝、
    定期購入なども該当し得る）
- RSI はバフェット・コードでは見られないので、証券会社アプリか TradingView 等の
  スクリーナーで最後に絞る。RSI は日々変わるため、**判定日を必ず記録**する。
- 決算日は「次回の決算発表予定日」を入れる（発表前後は値動きが荒れるため）。

## 実行できなかった理由（記録）

- リモート実行環境の外部通信ポリシーにより、buffett-code.com への接続が
  プロキシ段階で 403 拒否。kabutan / irbank / minkabu / Yahoo!ファイナンス等も同様。
- Web 検索（要約のみ）は可能だったが、検索結果の抜粋には銘柄コード・財務数値まで
  含まれず、「数字は出典を確認してから書く」ルールを満たせないためリスト化を見送った。
- 対応策：①手元の VSCode + claude で本メモを渡して実行する、
  ②リモート環境のネットワークポリシーで buffett-code.com 等を許可する。
